# Moonmind: local checkout

## เริ่มใช้

ต้องมี Node.js 24 ขึ้นไปพร้อม npm, RAM และพื้นที่เพียงพอสำหรับ dependency/ฐานข้อมูล ระบบใช้ Vinext, Vite และ Cloudflare Workers/D1 **จำลองบนเครื่อง** การติดตั้ง dependency ครั้งแรกต้องใช้อินเทอร์เน็ต ไม่ต้องมีบัญชีหรือบริการ Cloudflare สำหรับโหมดนี้

ดาวน์โหลดโค้ดหรือ clone repository ของตัวเอง เปิด terminal ในโฟลเดอร์ที่มี `package.json` แล้วรัน:

```sh
npm ci
npm run local
```

เปิด `http://127.0.0.1:5173` ผู้ใช้ใส่ชื่อเล่นและความยินยอมเพื่อเริ่มเลือกไพ่ทาโรต์/แชท ประวัติของชื่อเดิมกลับมาได้ผ่านคุกกี้ใน browser เดิม ชื่อเหมือนกันในคนละ browser ไม่แชร์ประวัติกัน

บน Windows ถ้าติดตั้ง dependencies ไว้แล้ว ให้ดับเบิลคลิก `Start-Moonmind.cmd` เพื่อเริ่มโหมด local เดียวกันได้ ตัวเปิดใช้ Node.js ที่ติดตั้งไว้ หรือ runtime ของ Codex ที่มีอยู่ในเครื่อง หากไม่พบจะแจ้งให้ติดตั้ง Node.js 24 ขึ้นไป รองรับเครื่องที่ไม่อนุญาตไฟล์ PowerShell `.ps1` โดยไม่ต้องแก้นโยบายการรันสคริปต์ ส่วน `Start-Moonmind.ps1` ยังคงใช้ได้บนเครื่องที่อนุญาตตามปกติ ถ้าไฟล์ `vite.local.config.ts` หาย ระบบจะแจ้งก่อนเตรียมฐานข้อมูลแทนการรายงานว่าพร้อมใช้งาน

เข้าโหมดผู้ดูแลของเครื่องที่:

```text
http://127.0.0.1:5173/signin-with-chatgpt?return_to=/
```

นี่คือ local sign-in จำลองของ development server ไม่ใช่บัญชี ChatGPT จริง ผู้ที่เข้าถึงเครื่องและพอร์ต localhost นี้ถือว่าเป็นผู้ดูแลที่เชื่อถือได้ การอ่าน/ลบประวัติยังใช้เงื่อนไขความยินยอมและการยืนยันชื่อเดิมของแอป ออกจากโหมดผู้ดูแลผ่าน `http://127.0.0.1:5173/signout-with-chatgpt?return_to=/`

ปิดด้วย Ctrl+C ใน terminal เมื่อเปิดอีกครั้งข้อมูลเดิมยังอยู่ ถ้าพอร์ตชน ให้ใช้:

```sh
npm run local -- --port 5317
```

ระบบไม่สลับพอร์ตเองและไม่รับ `--host` ภายนอก ถ้าพอร์ตยังถูกใช้งาน ให้หยุดโปรแกรมที่ใช้พอร์ตนั้นหรือเลือกพอร์ตอื่น

## ข้อมูลและความเป็นส่วนตัว

- `.moonmind-local/state/` เก็บ D1 บนเครื่อง คำสั่งเริ่มระบบใช้ migrations เฉพาะที่ยังไม่เคยใช้ ไม่ลบหรือสร้างฐานข้อมูลทับทุกครั้ง
- `.moonmind-local/worker/` เป็น config ที่สร้างเองโดย script และไม่มีคีย์ แอปโหมดนี้แยกออกจาก `.wrangler/`, `.sites-runtime/` และ `.dev.vars` ของ preview เดิมโดยสิ้นเชิง ไม่ย้าย/ลบข้อมูลเดิม ถ้าต้องย้ายข้อมูลจริงควรทำขั้นตอนสำรองและย้ายโดยเฉพาะก่อน
- ต้องเก็บคุกกี้ของ browser เดิมเพื่อกลับไปใช้ประวัติเดิม การสำรองฐานข้อมูลอย่างเดียวไม่ได้ย้าย browser session ไปอีกเครื่อง ควรปิดแอปก่อนสำรองทั้ง `.moonmind-local/` ไปยังที่ส่วนตัวที่ปลอดภัย
- การลบโปรไฟล์ผ่านผู้ดูแลลบข้อความและคำขอของโปรไฟล์นั้นด้วย จึงควรตรวจชื่อและผู้ใช้ก่อนยืนยันการลบ
- `.gitignore` กัน `.moonmind-local/`, `.wrangler/`, `.env*`, `.dev.vars*`, log/runtime เดิม และไฟล์ฐานข้อมูลที่รู้จัก อย่าเพิ่มไฟล์แชทหรือ backup ส่วนตัวด้วย `git add -f` ตรวจรายการไฟล์ทุกครั้งก่อนส่งขึ้น GitHub

โหมด local ใช้คำตอบตามกฎที่มากับ source โดยตั้ง provider เป็นค่าว่าง ไม่โหลดคีย์จาก `.dev.vars` เดิมหรือค่าตั้ง AI ในฐานข้อมูล และปิดหน้าบันทึกคีย์ภายนอก จึงไม่มีการเรียกโมเดล/API ภายนอกหรือค่า inference ต่อข้อความจากคำสั่งนี้ คุณภาพการสนทนาเป็นของโหมดตามกฎ ไม่ใช่การรัน large language model บนเครื่องโดยอัตโนมัติ

## ตรวจสอบ

```sh
npm run local:check
npm run test:local
npm run test:conversation
npm run check
```

`local:check` ตรวจ prerequisite และใช้ migration กับฐานข้อมูล local โดยไม่เปิดเว็บ การทดสอบ unit ตรวจขอบเขต Host/Origin การป้องกัน inherited credentials และการไม่เขียนทับข้อมูลเดิม `test:conversation` ตรวจการต่อเรื่อง คำปฏิเสธ การเปลี่ยนหัวข้อ น้ำเสียง และการบันทึกบทสนทนา โดยใช้ข้อมูลจำลองและไม่มีการเรียกโมเดลภายนอก ส่วน `check` ตรวจ TypeScript ขณะเปิด `npm run local` สามารถรัน HTTP check ในอีก terminal ได้:

```sh
node tests/local-http-smoke.mjs
```

HTTP check ใช้เฉพาะโปรไฟล์ชื่อสุ่มที่สร้างเพื่อทดสอบ แล้วลบทิ้งเอง ตรวจ guest isolation/return, tarot invitation, local owner, admin delete และการปิด provider ไม่ใช้ข้อมูลจริงของผู้ใช้ ถ้าเปิดพอร์ตอื่น ให้ตั้ง `MOONMIND_TEST_URL` เป็น URL localhost นั้นก่อนทดสอบ

ถ้า config ใน `.moonmind-local/worker/` ถูกแก้ script จะหยุดพร้อมข้อความและไม่เขียนทับไฟล์นั้น ให้สำรองและตรวจการแก้ไขก่อน อย่าลบฐานข้อมูลเพื่อแก้ปัญหาการตั้งค่า

## ขอบเขต GitHub และการเปิดสาธารณะ

GitHub เป็นที่เก็บ source/ประวัติการแก้ไขเท่านั้น `npm run local` เปิดเว็บเฉพาะเครื่องที่รัน ไม่ได้เผยแพร่จาก GitHub Pages และไม่ได้ทำให้คนอื่นเข้าได้ตลอดเวลา การเปิดสาธารณะต้องมี runtime, storage, authentication และการตั้งค่า HTTPS แยกต่างหาก ห้ามใช้ local owner sign-in ผ่าน tunnel, port forwarding หรือ reverse proxy เพราะสร้างเพื่อเครื่องที่เชื่อถือได้เท่านั้น
